# Laporan Penggunaan AI dalam Pengembangan Kasir Bisa

| Prompt/instruksi yang diberikan pada AI | Ringkasan hasil/output | Modifikasi pengembangan atau verifikasi yang dilakukan tim |
|---|---|---|
| Migrasikan aplikasi Kasir Bisa dari Flutter menjadi website dengan nama yang sama. Pertahankan nuansa biru dan fitur aplikasi. | AI membantu menyusun versi web Kasir Bisa dengan halaman kasir, katalog, rekap, Smart Insight, login, dan panduan. | Tim menentukan folder kerja website, membandingkan tampilan dengan aplikasi, memberi masukan desain, dan memeriksa hasil di browser. |
| Atur tampilan seperti aplikasi: bagian atas untuk scan dan transaksi, bagian bawah untuk katalog serta penambahan barang manual. | Tata letak kasir web disusun dengan area transaksi yang mudah diakses dan katalog untuk pengelolaan produk. | Tim meninjau alur kasir dan meminta penyesuaian ketika tata letak atau navigasi belum sesuai kebutuhan. |
| Gunakan database gratis dan jelaskan pilihan yang sesuai untuk aplikasi. | Cloudflare D1 dipilih untuk penyimpanan data, dengan Cloudflare Pages Functions sebagai penghubung API dan database. | Tim menyiapkan project Cloudflare, database, serta binding yang dibutuhkan. Nama project, nama database, dan ID database diperiksa karena sempat tertukar. |
| Buat fitur scan barcode dan pengelolaan produk manual. | Website mendukung pencarian/scan barcode, input manual, serta tambah, edit, dan hapus produk dengan harga, stok, kategori, dan barcode. | Tim mencoba alur katalog dan transaksi, melaporkan masalah dari website, dan memeriksa perubahan tampilan maupun data. |
| Tambahkan fitur untuk mengunggah foto produk. | Formulir produk mendukung JPG, PNG, dan WebP; gambar dipratinjau dan diperkecil sebelum disimpan. | Tim menguji pemilihan gambar dan meminta fallback gambar ketika produk belum memiliki foto atau gambar gagal dimuat. |
| Sediakan transaksi yang menghitung pembayaran, diskon, pajak, kembalian, dan stok. | Backend memvalidasi produk dan stok, menghitung total transaksi, menyimpan riwayat, lalu mengurangi stok setelah transaksi berhasil. | Tim menguji scan/input barcode, keranjang, pembayaran, pengurangan stok, dan tampilan rekap. |
| Putar efek suara setelah transaksi sukses. | Suara transaksi diputar setelah server mengonfirmasi transaksi tersimpan; kegagalan audio tidak membatalkan transaksi. | Tim mencoba alur pembayaran dan memeriksa agar suara hanya dijalankan setelah transaksi sukses. |
| Tambahkan Smart Insight dan jelaskan penggunaan API key dengan aman. | Smart Insight merangkum penjualan, produk terlaris, stok menipis, dan jam ramai; Helipod digunakan secara opsional dengan insight cadangan jika layanan gagal. | Tim mengatur API key sebagai secret Cloudflare, tidak menaruhnya di source code, dan melaporkan error yang terlihat untuk diperiksa. |
| Tambahkan login pemilik dan jelaskan cara mengganti akun. | Sistem autentikasi dibuat dengan sesi cookie aman dan perlindungan endpoint API. Pengelolaan akun kemudian dilengkapi melalui halaman Profil. | Tim menguji login dan melaporkan kegagalan melalui tangkapan layar serta inspect browser. Secret tidak dicantumkan dalam laporan ini. |
| Buat halaman Profil untuk mengubah username, password, dan foto profil. | Profil pemilik disimpan di D1; password di-hash, perubahan kredensial mengakhiri sesi login lain, dan foto profil dikompres sebelum disimpan. | Tim meninjau alur form. Password saat ini dipakai untuk verifikasi; password baru diisi pada kolom password baru dan konfirmasi. |
| Ubah navigasi menjadi hamburger menu dan buat panduan penggunaan. | Menu hamburger dipasang pada halaman utama, rekap, Smart Insight, panduan, dan profil. Panduan website dan dokumentasi proyek Markdown juga dibuat. | Tim memberi masukan agar panduan menjelaskan cara menggunakan fitur dan cara menangani kendala, lalu memeriksa tautan dan navigasi halaman. |
| Tambahkan pembayaran QR dan tanyakan cara mendukung beberapa kode QR. | Pengembangan QR Pembayaran mencakup pengelolaan QR, pilihan saat checkout, konfirmasi pembayaran manual, serta pencatatan metode/nama QR pada transaksi. Beberapa perubahan membutuhkan migrasi D1. | Tim menetapkan label dan ruang lingkup fitur, meninjau editor crop serta alur checkout, dan menguji migrasi di database lokal. Migrasi remote harus diterapkan hanya setelah target D1 dipastikan. |
| Buat dashboard Admin untuk mengelola akun dan data usaha. | Source menyediakan pengelolaan akun, status akun, produk/stok, transaksi read-only, QR Pembayaran, dan notifikasi internal dengan pembatasan akses backend. | Tim menguji source lokal dan memeriksa endpoint. Sebagian masalah produksi ternyata berasal dari Pages Function yang belum ada di deployment; perubahan lokal tidak dianggap otomatis sudah live. |
| Periksa error deployment, login, database, atau tampilan berdasarkan screenshot dan pesan Console. | AI membaca status HTTP dan pesan error untuk menemukan sebab, misalnya konfigurasi target D1, tabel/kolom migrasi yang belum tersedia, atau batas iterasi PBKDF2 pada Cloudflare Workers. | Tim menyediakan screenshot/log, memeriksa project Pages dan binding D1, serta memutuskan tindakan. Kredensial tidak dibagikan untuk pengujian. |
| Perbaiki kegagalan hash password karena batas runtime Cloudflare. | Iterasi PBKDF2 disesuaikan dari 310.000 ke 100.000 agar sesuai batas yang dilaporkan runtime Cloudflare Workers. | Tim menjalankan pemeriksaan sintaks, build, dan tes lokal alur pembuatan profil awal, login, serta akses profil. Keberhasilan lokal tidak dianggap bukti bahwa deployment produksi sudah diperbarui. |
| Buat dokumentasi teknis dan catatan aktivitas agar perubahan mudah dipahami serta dipresentasikan. | README, changelog, dokumentasi kebutuhan, arsitektur, database, fitur, panduan pengguna, dan catatan riwayat dikembangkan dalam Markdown. | Tim meninjau isi dokumen, meminta rangkuman yang mudah disalin, dan mencatat batasan deployment serta migrasi yang belum dilakukan. |
| Verifikasi hasil perubahan sebelum digunakan atau dipublikasikan. | Pemeriksaan yang pernah dilakukan mencakup `node --check`, build statis, uji migrasi SQLite lokal, pemeriksaan tautan/asset, dan pengujian API menggunakan mock atau environment lokal. | Tim melakukan uji browser, memeriksa hasil deploy dan endpoint Cloudflare, serta memberi umpan balik berdasarkan penggunaan. Deployment, migrasi remote, dan pengujian kredensial dilakukan hanya jika target dan izin sudah jelas. |

## Catatan

- AI digunakan sebagai alat bantu analisis, penulisan kode, debugging, dan penyusunan dokumentasi; keputusan desain dan prioritas fitur tetap diberikan oleh tim/pengguna.
- Sebagian perubahan hanya diperiksa secara lokal. Jangan menyatakan semua fitur sudah tersedia di website produksi tanpa memeriksa deployment yang sedang aktif.
- Jangan menuliskan password, API key, token, atau nilai secret ke laporan.
